## DEVHUB-A11Y-NESTED-INTERACTIVE (2026-07-16) — follow-up closed

Closed the `nested-interactive` follow-up logged above. Redesigned both
components' per-row DOM structure:

- **`SessionsPane`** (`apps/web/src/components/SessionsPane.tsx`): switched the
  whole list from the `listbox`/`option` ARIA pattern to `grid`/`row`/
  `gridcell`. A `role="option"` item must be a leaf (no focusable
  descendants — that's the violation) and `role="listbox"` may only own
  `option`/`group` children (confirmed empirically: moving the action buttons
  to be siblings of the option, even wrapped in `role="group"`, still tripped a
  NEW `aria-required-children` violation — axe's computed a11y tree flattens
  through generic/group wrappers, so any focusable descendant still reads as an
  illegal "child" of the listbox). A `gridcell` is explicitly designed to host
  exactly one focusable widget, so wrapping each action (select checkbox, pin,
  the "open session" button, rename) in its own `role="gridcell"` (a direct
  child of a `role="row"`, itself a direct child of `role="grid"`) satisfies
  both rules at once. `useListKeyboardNav`'s j/k/Home/End/Enter model is
  unchanged — it never depended on the `listbox`/`option` role names, only on
  `focusedIndex` + the container's own `onKeyDown`.
- **`ProjectsPane`** (`apps/web/src/components/ProjectsPane.tsx`): has no
  per-row action buttons today, so the simpler `listbox`/`option` pattern is
  kept, but the per-row `role="option"` element is now a non-focusable
  (`tabIndex={-1}`) `<div>` instead of a native `<button>` — closing the same
  hole preventively (a native button there was already a real, if currently
  harmless, deviation from the "option is a leaf, container owns focus"
  listbox model; the change keeps room to add a sibling action later without
  reintroducing `nested-interactive`).

New tests: `apps/web/src/components/nested-interactive-rows.test.ts` (7 cases,
full RTL mounts of both panes) — asserts the grid/row/gridcell structure
exists with zero `role="listbox"`/`role="option"` left in `SessionsPane`, that
no `gridcell` contains more than one focusable descendant or another
grid/row/gridcell, that the checkbox/pin/rename buttons are real reachable
`<button>`s, that clicking the row still opens the session, and that
`useListKeyboardNav`'s `j`/`Enter` keyboard flow still works end to end for
both panes.
